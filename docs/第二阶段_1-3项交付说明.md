# 第二阶段：数据基础、采购收货、审批纠错

版本：0.2.0。本次完成第1—3项的本地开发实现，保留第一阶段库存数据与审计记录。调拨、退货、真实连接器及生产部署不在本次交付范围内。

## 1. 数据基础与批量导入

- `schema_migrations` 记录数据库结构版本：v1 接管第一阶段十张表；v2 增加导入、采购、审批和冲正关系表。升级按顺序执行，已执行版本不重复执行，较新的未知版本会拒绝启动。启动与演示初始化均执行迁移。
- 本次为增加表的迁移，不修改原库存表和流水；后续字段修改必须增加新版本，不能编辑已应用的迁移。未提供降级命令；出现问题时停服并从升级前备份恢复。
- 本地库升级前使用 SQLite 在线备份保留 `.local/backups/before-phase2-20260926-162511.db`；升级前后原12条余额、14张单据、14条流水数量一致。备份不纳入Git。
- 商品、仓库、期初库存均支持UTF-8 CSV，Excel请另存为UTF-8 CSV。可下载空白模板、上传文件或粘贴内容；单批最多500行、正文最多100万字符。直接读取XLSX尚未实现。
- 服务端校验表头、行列数、必填字段、数量、时区、重复编码、商品/仓映射，逐行返回错误。出现任何错误不可执行整批导入。确认时再次校验，所有行同事务，失败全部回滚。
- 相同内容文件关联原批次；已应用批次再确认不会重复入账。不同文件重复商品编码会被唯一约束拒绝，期初库存还以仓库+商品的已有历史阻止再次导入。
- 期初库存支持G/Q/D及订单、调拨、冻结、安全量、线下/线上/待发布/待撤回额度。空数量视为0；良品必须覆盖各类占用与承诺。仅接受无库存历史的自营仓+商品组合，外部人工参考仓不可改账。
- 期初导入写单据、流水和待接入事件。占用为汇总余额，不会自动生成旧订单、旧调拨或执行其释放；真实切换前仍需原业务明细映射和对账。
- 商品、仓库单条新增也统一使用幂等键；相同请求重试返回原结果，不再仅依赖编码冲突。

## 2. 采购与分批收货

一张采购单对应一个自营仓、一个供应商和1—100个不同SKU。采购单号在商户内唯一；创建采购单不改库存。

流程：待收货 → 部分收货 → 已收齐；待收货/部分收货可填写原因关闭余量。关闭不会撤销已收库存，关闭后不可继续收货。

- 每次到货可收部分商品，逐行区分良品、待验、残次；三者之和计入净实收，只有良品增加可售基础。
- 同一采购单的到货凭证号不可重复，且不因操作人员或请求编号变化而失效。
- 每行不得超收；采购版本和库存版本均要匹配，防止并发重复收货。多行入账、采购进度、流水和待接入事件在同一事务完成。
- 页面可展开到货凭证、执行单据以及已冲正标记。已关闭未收数量单独展示。
- 无财务金额、付款、发票或供应商结算，不构成财务采购系统。

## 3. 双人审批与冲正

仓管或管理员可申请，必须由另一名管理员审核。现有演示账号的可用流程为：warehouse申请 → admin审核。管理员自己的申请不能自行通过或驳回。

- 调整只接受良品/待验/残次数量增减及必填原因；申请本身不改库存。
- 审批通过时再次校验库存版本、余额非负、所有占用与额度保护。库存变化后须驳回旧申请，再发起新申请；不可带着过期数量直接入账。
- 驳回只记录审核结果与意见，不改库存；每个申请只能处理一次，同请求重试可返回原结果。
- 冲正支持普通收货、线下交货、采购收货、审批调整；依据原流水的前后快照生成完整反向变化，包含销售曾消费的线下额度。
- 冲正通过时追加新单据和反向流水，记录原单据→冲正单据→审批单关系。原始单据和流水不删除、不覆盖；同一原单据只能冲正一次。重复待审申请不能产生重复反向入账。
- 采购收货冲正同步回退该行净实收与采购版本。已收齐单恢复为部分收货/待收货；已关闭采购单保持关闭。原到货凭证仍占用，纠正后的新收货须使用可追溯的新凭证号。
- 期初单据不可直接冲正，使用审批调整纠错；冲正单不能再冲正。冲正后库存不足以覆盖已承诺额度时会拒绝执行。
- 页面原单据选择器当前展示最近100条流水；API可按原单据ID发起更早记录的冲正。

## 接口与权限

所有写接口校验登录、来源和CSRF。除登录及导入预览外，以下写接口均要求8—120字符的`Idempotency-Key`；身份和商户由会话获取。

| 接口 | 用途 | 岗位 |
|---|---|---|
| GET /api/v1/imports/template/{kind} | 下载CSV模板 | 管理员 |
| GET /api/v1/imports | 最近100批导入记录 | 管理员 |
| POST /api/v1/imports/preview | 校验、保存预览 | 管理员 |
| POST /api/v1/imports/{id}/apply | 原批次原子导入 | 管理员 |
| GET /api/v1/purchases | 最近100张采购单与明细、到货记录 | 管理员/授权仓管 |
| POST /api/v1/purchases | 创建采购单 | 管理员/授权仓管 |
| POST /api/v1/purchases/{id}/receive | 分批收货 | 管理员/授权仓管 |
| POST /api/v1/purchases/{id}/close | 关闭未收余量 | 管理员/授权仓管 |
| GET /api/v1/approvals | 最近100张审批记录 | 管理员/授权仓管 |
| POST /api/v1/approvals | 调整或冲正申请 | 管理员/授权仓管 |
| POST /api/v1/approvals/{id}/review | 审核与原子执行 | 非申请人的管理员 |

前端将未确认结果的写请求保存在当前会话存储内；网络失败时只能使用原请求重试，避免新建请求造成重复操作。业务唯一约束另行防止重复到货凭证和重复冲正。

## 验证与已知边界

自动化测试：45项通过，包括原21项与新增24项。新增验证覆盖旧库升级与重复迁移、资料幂等、导入逐行报错、并发变更后的整批回滚、期初占用校验、防重复导入、多SKU采购、60+40分批收货、超收、重复到货凭证、关闭后禁止收货、并发收货、自审拒绝、过期审批、驳回、冲正额度恢复、采购净实收回退、重复冲正、事务故障回滚及跨商户/岗位隔离。

浏览器验收使用明确标记的演示数据：采购单PO-DEMO-P2-001分60件与40件收齐；导入商品DEMO-P2-IMPORT；仓管申请减少2件、管理员审核通过。随后由仓管申请冲正该调整、管理员审核，库存恢复2件；原调整与新冲正记录同时可查。验收后折叠收纳箱良品为429件（第一阶段329 + 采购100 - 调整2 + 冲正2），数据库完整性检查通过。

当前仍是本地开发版。PostgreSQL实际运行、迁移并发和性能未实测；尚无生产部署、定时备份/恢复演练、完整历史分页UI、账号管理UI或真实平台接入。数据库关系仍以应用校验为主，外键和生产审计权限需在后续数据库加固中补齐。不能将本次测试结果等同于完整PRD全部验收通过。
