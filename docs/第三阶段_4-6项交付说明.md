# 第三阶段：4—6项交付说明

版本：v0.3.0。验收日期：2026-09-27。范围：自建系统的仓间调拨、退货与质检、账号及试运行基础。第二阶段数据通过版本3增量迁移保留。

## 4. 仓间调拨

入口「仓间调拨」支持多商品草稿、预占、整单发出、分批签收与取消。仅允许同商户的两个不同本地权威仓。

| 状态变化 | 库存处理 |
|---|---|
| 草稿 → 已预占 | 来源仓调拨占用T增加，保护已有线下/线上额度 |
| 已预占 → 已发出 | 来源仓良品G和T同时减少，数量计入在途 |
| 已发出 → 部分签收/已完成 | 目的仓按实际签收增加G/Q/D，减少在途 |
| 草稿/已预占 → 已取消 | 有预占时释放T；发出后不可取消 |
| 在途差异 → 审核结案 | 对全部剩余在途申请短少结案，由另一管理员审核，记录损失 |

来源仓人员负责发出，目的仓人员负责签收。调拨版本与库存版本防止并发覆盖；签收凭证防重复。差异审批与后续签收冲突时拒绝旧审批。数量变更保留库存流水，业务状态和差异保留事件记录。

## 5. 退货与质检

客户退货必须关联原销售单，累计不超过原售出数量，实物先进入原仓待验Q。逐次质检将Q转为良品G或残次D，直至完成。未完成客户退货占用的Q不能被普通质检、供应商退货或库存调整审批挪用。

供应商退货关联原收货或采购收货单，累计不超过原实收；按G/Q/D实际出库，同时保护库存额度。采购历史实收保持不变，不自动重开采购单。退货、质检凭证在商户范围内按业务规则去重，事务失败整体回滚。

已有退货的原单禁止整单冲正，已冲正原单禁止退货。普通待验质检可处理采购/调拨等来源的非退货专属Q。页面原单选择来自最近100条流水；接口支持合法历史单据ID。

## 6. 账号与试运行

管理员可创建岗位账号、指定仓库、启停账号及修改权限。管理员覆盖本商户所有仓库，其他岗位必须明确授权；不能停用或降级自己。权限变化立即撤销该账号旧会话，事务执行时重新验证权限。管理操作保留审计记录。

密码采用哈希存储；账号响应、审计、幂等响应及参数校验错误均不返回密码输入。创建账号表单的密码不进入sessionStorage。当前未实现密码重置流程。

「账号与试运行」显示数据库版本和库存约束检查。SQLite可一键创建在线备份及独立恢复副本，校验SHA256、完整性及表行数，恢复副本清除会话。备份不通过HTTP下载接口暴露。恢复工具拒绝覆盖已有目标文件。

```sh
.venv/bin/python -m app.backup create --source .local/inventory.db --directory .local/backups
.venv/bin/python -m app.backup restore --source .local/backups/实际备份文件.db --target .local/recovery/全新文件名.db
```

PostgreSQL恢复演练使用独立生成的测试schema和目标数据库，通过pg_dump/pg_restore后逐表比较数据哈希，再验证迁移与库存。脚本仅清理自己创建的测试schema和数据库。

## 当前边界及投产前工作

本阶段完成本地试运行基础，并不代表生产部署验收。仍需真实环境容量与50请求/秒压测、生产认证和HTTPS部署、自动异地备份与恢复时限演练、监控告警以及真实商户试运行。

调拨支持一次整单发出、分批签收；尚无分批发出、多次部分损失结案、批次追溯或新业务单据的冲正流程。退货不处理退款、应付或结算。库存使用商品仓库库存池，不追踪单件来源。外部仓仍只读，平台连接器与Outbox发送器未接入。

当前为确定性库存业务系统。自然语言Agent、模型调用和自动执行助手尚未实现，不能将本阶段功能称为已完成的智能Agent。
