# 第四阶段：Agent助手1—3项

本文件保留1—3项历史验收记录；4—5项现已完成，见[后续交付说明](第四阶段_4-5项交付说明.md)。

版本v0.4.0，开发验收日期2026-09-28。模型按用户选择接入DeepSeek V4.1 Flash。用户明确要求本阶段先不考虑密钥，因此本次完成代码、隔离模型契约测试及本地数据页面验收，未进行真实付费模型调用。

## 1. 对话入口与模型接入

侧栏新增「Agent助手」。支持商品和仓库范围选择、示例问题、最近10条查询记录、查询中状态、错误提示、清空记录和数据依据展开。查询记录仅保存在当前页面内存，刷新或退出清空；每次问题独立解析，筛选持续生效，不推测上一轮的“它”指哪件商品。

服务端使用DeepSeek官方Chat Completions接口，固定模型deepseek-flash（V4.1 Flash）、非思考模式，最多输出768 tokens，一次问题仅接受一个plan_inventory_query工具调用。输出需通过严格的本地字段和枚举验证。模型不生成SQL、不接收数据库连接信息，也没有写库存工具。模型理解问题后，服务端读取账本并用确定性模板输出数字、异常依据和建议，不二次发送库存结果给模型进行自由改写。

未配置密钥时页面显示「模型待配置」，自然语言发送按钮不可用；可用「查询库存」「检查异常」按钮直接运行同一套权限受控查询。本地按钮不解析输入框中的自然语言，接口也拒绝混用；不会把本地结果伪装为模型回答。模型失败时明确显示错误，不静默切换为规则回答。

## 2. 库存查询助手

查询当前良品G、待验Q、残次D、订单占用R、调拨占用T、冻结H、安全量B、可分配、线下可用和可见在途。

- 可分配 = G − R − T − H − B。
- 线下可用沿用既有库存接口的额度计算，不消费线上承诺。
- 按仓库与SKU分别列示，不混加不同商品单位。
- 人工参考仓明确标注快照来源；线下可用返回null，不作可售承诺。
- 无库存记录不解释为库存为零；商品或仓库有歧义时要求选择。
- 每次结果包含查询时间、账本/调拨来源ID、版本和更新时间，附当前查询范围。
- 调拨在途 = 发出 − 签收 − 已确认损失。仅管理员及仓管可以查询；店员明确显示未纳入调拨信息。

## 3. 异常分析助手

| 规则 | 判断依据 | 建议边界 |
|---|---|---|
| 可分配偏低 | 本地仓可分配 < 20 | 提醒核对占用与需求，不预测缺货或自动补货 |
| 待验未处理 | 本地仓Q > 0 | 建议核对退货及普通待验，不凭余额年龄判定超期 |
| 调拨未签收 | 在途 > 0 | 提醒确认签收；距发出满72小时增强关注提示，不认定丢货 |

阈值20和72小时是本阶段固定演示规则。支持按规则筛选；任意自定义阈值、历史时点和走势问题需要澄清，不支持需求预测。未触发规则不代表业务没有其他异常。

每项提示包含计算依据、建议及业务页面入口。页面入口只跳转，不自动执行动作。查询最多处理1000条对应数据，超出要求缩小范围，不将截断结果描述成全量结论。

## 权限与数据边界

所有请求使用现有登录会话，POST要求CSRF。商户和仓库权限由服务端决定，模型只提供名称片段；用户选定的SKU/仓库范围不能被模型扩大。模型请求前验证筛选权限，返回后重新认证，读取时复查角色授权，响应前再次验证会话。

SQLite显式只读事务快照，PostgreSQL使用REPEATABLE READ；不新增业务表，不修改余额、流水或单据。数据库版本继续为1/2/3。没有HTTP密钥设置接口，也不把密钥发送到前端。

每账号最多一个并发查询；每分钟最多10次模型请求。限流为当前进程内实现，多进程生产环境仍需共享限流。查询编号、模式、耗时及结果类型通过inventory.agent日志器记录；不记录原始问题、模型输出、密码或库存值。默认日志配置可能不显示INFO级记录，生产需另行配置收集；查询编号并非新增的持久审计表。

## 配置与启动

无需密钥即可启动并验收本地查询：

```sh
./scripts/run.sh
```

后续启用真实DeepSeek请求，可以为服务进程设置DEEPSEEK_API_KEY环境变量；或将仅含一行密钥的文件保存到项目.local/deepseek-api-key，权限必须0600。文件已由.local忽略规则排除。环境变量优先；不会自动读取.env。

接口地址固定为https://api.deepseek.com/chat/completions，不接受浏览器指定URL或工具URL；拒绝HTTP跳转，避免凭据被转发。配置后刷新页面显示「已配置」，此状态只表示存在密钥，不证明账号额度或模型连通性。问题文本和选中的商品/仓库名称将发送至DeepSeek；库存账本及查询结果留在本机。

接口：GET /api/v1/agent/status，POST /api/v1/agent/ask。Ask.mode为model/inventory/issues；本地模式只使用显式筛选。完整结构见openapi.json。
