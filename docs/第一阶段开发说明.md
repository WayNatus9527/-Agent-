## 架构和并发选择

浏览器只调用服务端业务接口；tenant_id、owner_id和actor_id从登录会话派生，不能由业务请求任意指定。当前单租户单货主模型保留tenant/owner字段，不提供跨货主转移。

SQLite写事务使用BEGIN IMMEDIATE，在读取幂等记录前获取写锁。PostgreSQL分支使用按tenant_id的事务级advisory lock；这是第一阶段偏保守的串行实现，不声称达到50写/秒目标。后续经实测再缩到SKU/仓组合锁。

库存变更依次完成权限、源仓、SKU、幂等键、expected_version和额度校验，然后写余额、业务单据、只追加流水、Outbox、结果记录。任一步异常整体回滚。同一用户同一幂等键相同内容返回原结果，不同内容拒绝。

收货将g/q/d分别累加，且总数必须大于0；销售先使用线下已分配额度，不足部分使用未分配量，禁止占用线上、待发布或撤回中承诺。销售扣G且扣已消费的线下额度，不把款项当库存。

数据库模型暂由应用校验实体归属和关系；生产前还需补数据库外键/审计权限、独立只读账号及迁移约束。未提供直接改余额API。

## API契约

本地启动后 `/docs` 提供交互式OpenAPI，`/openapi.json`为机器可读契约，仓库保留本阶段快照于 `docs/openapi.json`。

库存写接口必须携带会话cookie、`X-CSRF-Token`及`Idempotency-Key`；修改库存必须提供读取到的`expected_version`。新商品首次入账版本为0，已存在组合从查询结果取版本。

| 方法与路径 | 用途 |
|---|---|
| POST /api/v1/session | 登录，返回CSRF令牌并写入HttpOnly cookie |
| GET /api/v1/session | 查询会话 |
| DELETE /api/v1/session | 注销会话 |
| GET /api/v1/bootstrap | 当前商户授权商品、仓库及连接状态 |
| GET /api/v1/inventory | 授权仓库存，可传warehouse_id |
| GET /api/v1/inventory/export | CSV导出 |
| GET /api/v1/ledger | 流水；limit为1至200，offset非负 |
| GET /api/v1/documents | 最近100张已完成业务单据 |
| POST /api/v1/receipts/confirm | 单规格收货入账 |
| POST /api/v1/sales/confirm | 线下现货交货出库 |
| POST /api/v1/skus | 管理员创建规格，唯一编码防重复 |
| POST /api/v1/warehouses | 管理员创建仓库，唯一编码防重复 |

基础资料创建目前依赖唯一编码防重复，不支持库存写接口的原结果重放；需在扩大写接口时统一幂等协议。登录/注销不使用库存幂等键。

错误码：INSUFFICIENT_STOCK、VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、READ_ONLY_WAREHOUSE、FORBIDDEN、NOT_FOUND、UNAUTHENTICATED、CSRF_REJECTED、ORIGIN_REJECTED、DUPLICATE、DATABASE_UNAVAILABLE。字段验证采用HTTP 422。数据库忙或连接故障不向前端暴露内部错误。
